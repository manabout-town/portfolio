# 포트폴리오 우주 리디자인 — 설계

작성 2026-08-07 · 대상 `~/Desktop/portfolio/index.html` · 라이브 배포 Vercel(`portfolio`)

## 1. 목표와 성공 기준

취업용 포트폴리오를 심우주 항해 경험으로 재구성한다. Three.js로 실제 3D 궤도 공간을 만들고,
프로젝트 9개를 천체로 띄운다. 각 천체의 표면에는 그 프로젝트의 실행 데모 영상이 감긴다.

성공 기준은 "멋있다"가 아니라 아래 숫자다. 하나라도 미달이면 그 단계는 완료가 아니다.

| 항목 | 기준 |
|---|---|
| 첫 텍스트 표시(FCP) | 1.5초 이내. Three.js 로드와 무관해야 한다 |
| 데스크톱 프레임 | 55fps 이상 (1440×900, DPR 상한 1.5) |
| 추가 JS | three.js 86.5KB gzip (0.185.1 실측). 그 외 라이브러리 0 |
| 모바일(≤640px) | Three.js를 **로드하지 않는다**. 현행 정적 세로 레이아웃 유지 |
| reduced-motion | Three.js를 로드하지 않는다. 현행 정적 레이아웃 유지 |
| 콘솔 에러 | 0 |

이탈은 첫 화면 지연과 저사양 프레임에서 발생한다. 위 표의 3·4·5행이 그 방어선이다.

## 2. 무엇을 바꾸고 무엇을 지키는가

**지킨다**
- 색 계보. 버건디 → 성운 자홍, 골드 → 별빛 백금으로 **계승**한다. 팔레트를 버리면 지금의 절제된
  결이 사라지고 흔한 우주 템플릿이 된다.
- 프로젝트 텍스트의 DOM. 카드 본문·상세 모달은 지금처럼 HTML에 남는다. 캔버스 안 텍스트는
  선택·검색·스크린리더가 전부 죽는데, 채용담당자가 보는 사이트에서 그 손실은 임팩트로 갚지 못한다.
- 수치의 출처. 화면에 적는 테스트 수·커밋 수·마이그레이션 수는 전부 기존 데이터에서 온다.
  우주 서사를 입히면서 없는 숫자를 지어내지 않는다.

**바꾼다**
- 배경: 직접 작성한 fbm 셰이더를 심우주 성운으로 재도장 (색·밀도·흐름 속도)
- 프로젝트 구간: 2D 깊이 필드 → Three.js 실제 3D 궤도
- 전 구간 문구: 발사 → 항해 → 관제 로그 → 미션 타임라인 → 교신 종료의 서사로 통일

## 3. 구조

### 3.1 계층

```
[레이어 0] 성운 배경   — 풀스크린 쿼드 ShaderMaterial (기존 fbm 이식, 심우주 팔레트)
[레이어 1] 별          — Points 2만개, 3레이어 시차. 카메라 이동에 따라 깊이차로 흐른다
[레이어 2] 천체 9개    — 저폴리 구체 + VideoTexture(프로젝트 데모 영상) + 림라이트
[레이어 3] DOM 오버레이 — 카드 텍스트. three가 투영한 천체 좌표를 CSS transform으로 따라간다
```

레이어 3이 핵심 결정이다. 3D는 공간과 인상을 담당하고, 의미(무엇을 왜 만들었는가)는 DOM 텍스트가
담당한다. 이 분리 덕에 JS가 죽어도, 셰이더가 실패해도 포트폴리오로서의 기능은 남는다.

### 3.2 천체 = 실행 데모

각 프로젝트 구체 표면에 `media/<name>.mp4`를 `VideoTexture`로 감는다. 행성이 곧 앱 화면이 되므로,
우주가 배경 장식이 아니라 **작업물 자체의 전시 형식**이 된다.

- 영상 9개는 이미 있다: hairpin · photo · summer · goesby · naedon · momnote · devfit · takca · sevmerge
- 세로 영상(390×844)이 8개, 가로(1280×800)가 1개(SevMerge). UV 매핑을 영상 비율에 맞춰
  보정하지 않으면 구체 위에서 심하게 늘어난다. 비율별 UV 스케일을 재질 uniform으로 넘긴다.
- **동시 재생은 화면 근처 3개까지.** 나머지는 `pause()`. 9개 동시 디코딩은 저사양에서 즉사한다.
- 영상 로드 실패·디코딩 불가 시 해당 천체는 단색 + 림라이트로 자동 강등한다(검은 구체 금지).

### 3.3 카메라와 스크롤

스크롤 진행도가 카메라의 궤도 위 위치를 결정한다. 현재 `pin` 섹션이 하던 일(스크롤 → 카드 사이 통과)을
그대로 3D로 옮기는 것이라 스크롤 문법은 사용자에게 낯설지 않다.

- 천체 9개는 나선 궤도 위에 배치. 카메라는 궤도를 따라 이동하며 각 천체 앞에서 잠시 정렬된다
- 정렬된 천체만 DOM 카드가 뜬다. 나머지는 흐려지고 멀어진다
- 좌하단 진행 라벨은 유지하되 표기를 항해 좌표계로 바꾼다

### 3.4 구간별 서사 (전 구간)

| 구간 | 현행 | 우주 |
|---|---|---|
| 히어로 | "아홉 개를 / 만든 게 아니라 / 내보냈다" | 발사 시퀀스. 문구는 유지 — 이미 '내보냈다=launch'와 붙는다 |
| 소개 | 일하는 방식 | 항해 일지. 혼자 끝내는 범위 = 단독 항해 장비 목록 |
| 터미널 | `~/shipped — zsh` | 관제탑 로그. 프롬프트·라벨만 교체, 값은 기존 P 배열에서 그대로 파생 |
| 프로젝트 | 2D 깊이 필드 | **Three.js 3D 궤도** |
| 2026 간트 | 월별 막대 | 미션 타임라인. 막대 = 궤도 구간 |
| 푸터 | 연락처 | 교신 종료 |

문구 교체는 **은유만** 바꾸고 사실은 건드리지 않는다. 커밋 수·테스트 수·상태(운영 중/대기)는 그대로다.

## 4. 성능 설계

### 4.1 로딩 순서

1. HTML/CSS만으로 히어로 텍스트와 CSS 그라디언트 정지 배경을 즉시 그린다
2. `load` 이후 자격 검사: 모바일·reduced-motion·WebGL 미지원이면 **여기서 끝**. 현행 정적 레이아웃이 최종 화면이다
3. 통과한 경우에만 `three.module.min.js`를 동적 import → 씬 구성 → 정지 배경 위로 페이드인

three.js는 `vendor/three.module.min.js`로 저장소에 넣는다(빌드 도구가 없고 CDN 의존을 만들지 않기 위해).

### 4.2 적응형 강등

프레임 시간을 60프레임 창으로 샘플링한다. 45fps 미만이 2초 지속되면 단계적으로 낮춘다.

| 단계 | 조치 |
|---|---|
| 0 (기본) | 별 20,000 · 구체 세그먼트 64 · 동시 영상 3 |
| 1 | 별 8,000 · 세그먼트 32 · 동시 영상 2 |
| 2 | 별 3,000 · 세그먼트 16 · 동시 영상 1 · 성운 해상도 절반 |

강등만 하고 승격은 하지 않는다(진동 방지).

### 4.3 그 외

- DPR 상한 1.5, `antialias:false` — 기존 배경 셰이더와 같은 기준
- 탭 비활성(`visibilitychange`) 시 렌더 루프와 영상 재생 정지
- 리사이즈는 디바운스 150ms

## 5. 파일 구조

현행은 `index.html` 한 파일(81KB)이다. 3D 코드를 여기에 더 밀어넣으면 한 파일이 사람도 도구도
다루기 힘든 크기가 된다. 3D만 분리한다.

```
index.html              페이지 · 기존 스타일/스크립트 (성운 셰이더 재도장, 문구 교체)
js/cosmos.js            Three.js 씬 — 자격 검사 통과 시에만 동적 import 되는 진입점
vendor/three.module.min.js   three 0.185.1 (86.5KB gzip)
media/*.mp4             기존 데모 영상 9개
```

`js/cosmos.js`가 노출하는 것은 `init(el, projects)` 하나다. 페이지는 3D 내부를 모르고,
3D는 페이지의 DOM 구조를 모른다. 둘 사이 계약은 프로젝트 배열과 "천체 i의 화면 좌표" 콜백뿐이다.

## 6. 검증

각 단계는 Playwright 실측으로 닫는다. 눈으로 "부드럽네"는 완료 근거가 아니다.

- FPS: `requestAnimationFrame` 샘플링 300프레임 평균/최저 기록
- FCP: 히어로 텍스트 표시 시각 측정. Three.js 비활성 상태에서도 측정
- 폴백: 모바일 뷰포트·`prefers-reduced-motion`으로 각각 로드해 three 요청이 나가지 않는지 네트워크 로그로 확인
- 콘솔 에러 0
- 스크린샷: 데스크톱 각 구간, 모바일 폴백

## 7. 리스크

| 리스크 | 대응 |
|---|---|
| 영상 9개 텍스처가 저사양에서 프레임 붕괴 | 동시 재생 3개 제한 + 적응형 강등 + 실패 시 단색 강등 |
| 우주 = AI 템플릿 클리셰로 보임 | 팔레트 계승 + 천체 표면이 실제 작업물이라는 은유가 장식을 근거로 만든다 |
| 3D가 텍스트를 잡아먹어 포트폴리오 기능 상실 | DOM 오버레이 유지. 3D는 공간만 담당 |
| 한 파일이 감당 못 할 크기가 됨 | `js/cosmos.js` 분리, 계약 최소화 |
| 되돌리기 어려움 | 프로젝트 구간부터 착수. 각 단계 독립 커밋 |
