    마지막 팀 프로젝트로 7명이 4주간 Java 21 · Spring Boot 3.4.5 기반의 역제안 입찰 플랫폼(SevMerge)을 만들었습니다. 저는 결제·정산 계층을 맡았고, 팀은 거기에 Spring AI로 의뢰 작성 도우미를 붙였습니다.

    거기서 배운 트랜잭션 경계와 상태 머신, 인가 계층을 들고 나와 그 뒤 넉 달 동안 혼자 열여섯 개를 내보냈습니다.

    회사가 나눠 맡는 일을 한 사람이 이어서 합니다. 기획, 화면, 서버, 약관, 심사, 배포, 그리고 운영까지. 그래서 "동작하는 데모"가 아니라 결제가 일어나고, 심의를 통과하고, 사용자가 매일 여는 서비스를 내놓습니다.

    How I work with AI

    AI를 도구가 아니라 설비로 씁니다.

    "AI한테 시켰다"는 결과가 매번 다릅니다. 저는 잘 나온 절차를 그 자리에서 파일로 굳혀 둡니다. 다음 프로젝트는 같은 절차를 다시 밟고, 그래서 열여섯 번째가 첫 번째보다 빠르고 안전합니다. 아래는 제 로컬 ~/.claude에 실제로 들어 있는 것들입니다.

    01

    반복을 스킬로 굳힌다

    직접 쓴 스킬 7종 · 5,232줄. 프롬프트 모음이 아니라 참조 문서와 실행 스크립트가 딸린 절차서입니다.

    • apps-in-toss-ship — 토스 미니앱 배포. ait build가 vite를 안 도는 버그, 4031 권한 오류, 웹뷰 CSP로 웹폰트가 죽는 상황까지 회피 절차로 적어 뒀습니다.
    • app-demo-reel — 배포된 앱을 헤드리스 브라우저로 직접 조작·녹화해 세로 릴스와 GIF로 뽑는 스크립트 2개.
    • logo-craft — 로고 납품 워크플로 + verify-logo.mjs(SVG 검증 시트 생성기)와 블라인드 판독 스크립트.
    • red-blue-battle — 내 앱을 상대로 레드팀/블루팀 서브에이전트를 붙여 공격·패치를 라운드로 반복.
    • cinematic-onepager · nalgom-shorts · naver-blog — 원페이지·숏츠·블로그 발행 파이프라인.
    02

    검증은 눈이 아니라 수치로

    "괜찮아 보인다"는 두 번 반려당하고 나면 못 믿게 됩니다. 화면 판정은 Playwright가 재서 숫자로 답하게 했습니다.

    • 데브핏이 토스 심사에서 탭바 문제로 2회 반려됐습니다. 원인은 하단 풀폭 바가 토스 네이티브 탭과 실루엣이 겹치는 것. 고친 뒤 눈으로 보지 않고 navBottomGap=20px, pillWidth=259/430 중앙을 어서션으로 고정했습니다.
    • 입력 폼은 320·390·430 폭 × 폰트배율 1.0·1.3·1.5, 아홉 조합에서 가로 오버플로가 0인지 프로브로 확인합니다.
    • 이 포트폴리오에 실린 데모 영상도 사람이 화면을 녹화한 게 아니라 스크립트가 브라우저를 몰고 다니며 찍은 것입니다.
    03

    코드보다 스펙을 먼저 쓴다

    저장소마다 docs/specs와 docs/plans가 있습니다. 설계를 글로 확정하고, 확정된 것만 구현합니다. 중간에 방향이 바뀌면 코드가 아니라 문서를 먼저 고칩니다. 그래야 세션이 끊겨도 다음 작업이 같은 자리에서 이어집니다.

    소수팡(인수분해 퍼즐)은 풀구현 뒤에야 재미가 없다는 걸 알고 폐기했습니다. 그 뒤로는 코어 규칙을 프로토로 먼저 검증합니다. 실패에서 만든 규칙이라 안 잊습니다.

    04

    규칙은 문서가 아니라 불변식으로

    사람이 지켜야 하는 규칙은 언젠가 빠집니다. 빠지면 실수가 아니라 위반입니다.

    • 유라연은 아이용 제품이라 어린이제품 KC 안전정보 표기가 법적 의무입니다. 설명란에 적는 대신 신고번호가 비어 있으면 상품이 아예 노출되지 않게 만들었습니다.
    • 공급처 이미지가 placeholder인 상품은 등록 스크립트가 거부합니다 — 심사 100% 반려 사유라서.
    • 메일 초안 생성기는 치환이 덜 된 자리(대괄호·중괄호 잔재)가 남으면 생성 자체를 거부합니다.

    제품 안에 들어간 AI

    쓰는 것만이 아니라 넣는 쪽도 합니다. 아래는 전부 실제 코드에 있는 기능입니다.

    탁카 — 신분·사업자 서류 검증

    Claude Vision이 사업자등록증·운전면허증 이미지를 읽고 레이아웃 일치 · 직인 유무 · 디지털 조작 흔적 · 판독 가능 품질을 고정 JSON 스키마로 판정합니다. 여기에 Clova OCR과 국세청 사업자상태 API를 겹쳐 3중 검증으로 통과 여부를 냅니다. 업로드는 JPG·PNG·WEBP 10MB 이하만 받고, 위반 사유는 사용자 문장으로 되돌려 줍니다. 라우트 한 파일 598줄.

    @anthropic-ai/sdk · Clova OCR · 국세청 API · Next.js Route Handler
    포토 아뜰리에 — 온디바이스 추론

    얼굴 랜드마크(face-landmarks-detection)와 인물 세그멘테이션(MediaPipe SelfieSegmentation)을 서버 없이 브라우저 안에서 돌립니다. 사진이 기기 밖으로 나가지 않는 게 이 앱의 기능이라 업로드 경로를 아예 만들지 않았습니다. 대신 tfjs는 무거우니 해당 탭을 처음 열 때만 동적 import해서 진입 번들에서 뺐습니다. 모델은 자체 호스팅.

    TensorFlow.js · WebGL backend · 지연 로드 · 모델 자체 호스팅
    SevMerge — 의뢰 작성 도우미 (팀)

    Spring AI 1.1.1로 Gemini 2.5 Flash를 붙여, 자연어 한 줄에서 제목·카테고리·예산·설명 초안을 만들고 플랫폼 Q&A 챗봇으로도 씁니다. 의뢰 작성에 익숙하지 않은 사용자의 진입 장벽이 팀이 정의한 문제였습니다.

    Spring AI · Gemini 2.5 Flash · Java 21
    푸른새싹 — AI 크롤러를 전제한 SEO

    빌드가 llms.txt와 llms-full.txt(카탈로그 렌더)를 생성합니다. 색인 스위치를 켜면 robots가 GPTBot · ClaudeBot · PerplexityBot · Google-Extended는 명시 허용하고 학습 전용 크롤러(CCBot)만 막습니다. 실데이터 전에는 전 페이지 noindex — 이 값은 vercel.json에 두지 않고 사람이 콘솔에서 켭니다.

    llms.txt · robots 정책 · JSON-LD · 색인 스위치
